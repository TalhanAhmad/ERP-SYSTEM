# Screens

Implemented: /finance, a protected setup-status screen with a return-to-workspace link. It shows no amounts, inactive buttons, sample transactions or false reports. Unselected users receive an unavailable page; the nav link appears only for an active selected administrator when the feature flag is enabled.

Planned F09 onward: Template B searchable registers, compact filtered totals, 25 rows/default and 100 maximum, stable server sorting, detail drawers, keyboard/mobile support and explicit loading/error/stale states. Cash register rows represent posted cash movements only. Draft previews and Post confirmation precede immutable postings; correction is a reversal/credit workflow.

F04 adds /finance/access: current owner/selected-access status, owner-only grant/revoke/transfer/cancel forms, recipient acceptance, current-password/fresh-TOTP inputs, version conflicts, bounded recent restricted audit history and no plaintext credential persistence. Read-only selected users cannot access owner controls; unselected/lower-role users cannot open the page.

## F05 setup screens

/finance/accounts has searchable active/archive/type filters, bounded server pagination (25 default, 100 maximum) and stable code/id sorting. /finance/accounts/new and /finance/accounts/{id} expose owner-only classification, parent group, control/contra/cash-equivalent mapping and archive/reactivate; used mapping inputs are disabled while names remain editable. /finance/periods lists explicit inclusive ranges and owner creation; /finance/periods/{id} permits owner amendments and unused voiding, with OPEN/VOID/CLOSED read-only states as appropriate. Selected administrators can read lists/details/history but receive no mutation controls. Unselected/lower roles are denied server-side.

Owner actions require reasons, fresh password and hosted fresh TOTP, with private responses and version/conflict messages. Credentials clear after each request; retry state contains business fields only. Forms are disabled before hydration and have POST fallback. Named focusable horizontal table regions support keyboard scrolling on mobile. Empty/invalid-filter/no-record states are explicit; no fake balances or fiscal defaults are displayed. Account parent options show the first 100 active groups and retain the current parent; searchable complete parent selection/shared drawers remain F09–F10 work.

## F09–F10 delivered registers and drawers

Shared FinanceRegister now serves account, period, journal, party and cash-account lists. It has stable bounded server pagination, typed search/state/kind/date/order filters as appropriate, explicit invalid/empty/loading/retry states and full-filter original journal totals. Row anchors progressively open full records without JavaScript; JavaScript opens a native dialog with Summary/Lines/Journal/History and validated Edit draft when available. Only implemented sections appear. Draft editing refreshes the drawer after save/conflict reload. Posted rows are read-only; full detail offers explicit reviewed Post or dated reversal/void actions by state. Original/reversal lines are retained separately.

New /finance/journals (+new/{id}), /finance/parties (+new/{id}), /finance/cash-accounts (+new/{id}) reuse fresh-auth forms. Owner setup controls are absent for selected read-only master users; selected administrators can create ordinary journal adjustments. Account/group/cash choices have real 25-row search/pagination and retained current selection, resolving F05’s bounded first-100 parent limitation. Optional project/person selectors remain bounded to100 active records with current values retained; these are not broad user directory endpoints.

Keyboard focus, native Escape/focus return, named horizontal table regions and 360px automated WCAG scans passed. Retry after a committed 503 retains the business request key without retaining credentials. No controls bypass their future registers, and no fake cash movement/report/attachment/allocation tabs or balances are shown.

## F26 asset lifecycle

/finance/asset-movements offers a searchable bounded private register with asset/state filters and source links. An asset’s detail links to monthly generation, reviewed impairment/adjustment/disposal/policy drafts and its retained movement history. /new?assetId=…&generate=1 generates only a monthly draft; detail separately offers review/edit/refresh/post/void/reopen or dated reversal according to current state. Exact current cost and carrying values reflect immutable events. Initial policy inputs and unused-registration void controls lock after use; location/custody remain editable. Accumulated-depreciation and expense selectors are restricted to the appropriate reviewed controls/classes. Posted journal lines, register-only events, original/reversal links and private audit history are visible to selected administrators only. Cash register disposal entries link to their typed source. Ordinary ERP project/person DTOs contain no financial amounts.
